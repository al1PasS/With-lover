# 拾光 · Couple Memory

按照《情侣日常记录网站方案》搭建的独立项目。参考项目 MBG 与 SharedMoments 保持原样，未复制其后端或匿名读写配置。

当前交付是可自托管的双人私有 MVP：包含交互前端、Java API、PostgreSQL 持久化、自动 HTTPS、健康检查与备份入口。图片私有对象存储、异地备份自动化和大规模压力验收仍属于后续生产加固范围。

## 现在可以体验什么

- 首页：双人昵称、在一起天数、手账封面、最近回忆、纪念日、足迹入口。
- 时光：关键词和标签筛选（同步地址栏）、回忆详情、上一篇/下一篇。时光和记录盒支持点赞、评论、作者和精确到分钟的发布时间；愿望单标注提出人。
- 相册：批量导入、照片网格、大图阅读、指定封面；足迹：独立城市长卷、排序管理、手机完整横幅与展开细读。
- 示例编辑：新建、编辑、草稿、私密/公开摘要、删除和恢复、添加纪念日。
- 桌面/手机适配、手机四项底部导航、系统深色模式与手动切换、减少动态效果支持。

示例中的人物、照片和故事不是用户真实数据。示例模式使用浏览器 `localStorage` 保存编辑结果，不会向 API 提交；登录状态只保留在当前标签会话。点击“进入我们的小世界”即可进入示例编辑，无需真实密码。未登录页面不会渲染记录盒、愿望、游戏或相册中的虚拟私密内容。

## 本地启动前端

需要 Node.js 24（开发验证版本 24.11.1）。

```sh
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

访问 http://127.0.0.1:5173 。默认是演示模式。接口联调时创建 `frontend/.env.local`：

```dotenv
VITE_DEMO=false
```

Vite 将 `/api` 转发至 `localhost:8080`，真实模式不会因为 API 故障而退回演示登录。真实数据不存入 localStorage、IndexedDB 或 Service Worker。

`VITE_DEMO` 是编译时模式开关：不设置或设为 `true` 时只使用浏览器演示数据；设为 `false` 时调用 Spring Boot API，并由 PostgreSQL 持久化。正式 Docker 镜像已经固定使用 `VITE_DEMO=false`。

## 后端与数据库

Java 21，Spring Boot 3.5.16，Spring Security、Spring Session JDBC、Argon2id、JPA、Flyway、PostgreSQL。

已实现：

- 匿名会话检测、CSRF 获取、双人登录、持久会话 Cookie、退出与会话销毁。
- IP 与账户登录尝试限制；无注册及第三账户创建接口，数据库只允许账户 ID 1、2。
- 回忆公开白名单 DTO、私有列表、创建、修改、软删除、恢复；公开查询排除草稿与回收站。
- 独立公开摘要必填校验；版本冲突返回 409；纪念日查询与创建。
- 管理员访客可见设置：整站完全私密，或按首页、时光、纪念日、相册、足迹分别开放。精选公开模式同时允许访客播放当前背景音乐，但不开放曲库或管理；完全私密仍拒绝公开音乐。公开接口在服务端再次校验，不能通过直接请求绕过前端。
- Flyway 建表包含用户、会话、回忆、纪念日，以及后续媒体、相册、地点关联、任务和审计表。

注意：当前公开设置会公开所填标题、完整日期、城市和摘要。方案中的**独立公开标题、日期精度选择与逐张照片授权**仍需实现后再作正式隐私验收。

```sh
cp .env.example .env
# 编辑 .env，设置随机 DATABASE_PASSWORD。
# 仅本机 HTTP 联调时将 COOKIE_SECURE 设为 false。
docker compose up -d database
```

## 正式部署

推荐部署到一台安装了 Docker Engine 与 Docker Compose v2 的 Linux 服务器。生产链路为：

```text
互联网 → Caddy（自动 HTTPS）→ Nginx（前端与 /api 反向代理）→ Spring Boot → PostgreSQL
```

部署前需要：

- 一个已经解析到服务器公网 IP 的域名；
- 防火墙放行 TCP 80、TCP 443 和 UDP 443；
- 至少 2 GB 内存；
- 不要将 `.env`、数据库备份或真实照片提交到 Git。

首次部署：

```sh
cp .env.example .env
# 编辑 .env：填写至少 24 位随机 DATABASE_PASSWORD 和真实 DOMAIN。
# COOKIE_SECURE 在正式环境必须保持 true。
./scripts/deploy.sh
./scripts/init-accounts.sh
```

账户初始化会在终端中依次要求填写两位用户的用户名、昵称与密码。第一个账户拥有管理员角色，第二个账户为普通成员；初始化只允许执行一次，不会覆盖已有账户。

查看服务状态和日志：

```sh
docker compose -f compose.yaml -f compose.prod.yaml ps
docker compose -f compose.yaml -f compose.prod.yaml logs -f --tail=200
```

更新部署：

```sh
git pull --ff-only
./scripts/backup.sh
./scripts/deploy.sh
```

`deploy.sh` 会拒绝示例密码、少于 24 位的数据库密码、示例域名及不安全 Cookie 配置。正式镜像固定以 `VITE_DEMO=false` 构建，编辑内容会进入 PostgreSQL，不会在退出后恢复成示例数据。

### 备份

手动创建 PostgreSQL 自定义格式备份：

```sh
./scripts/backup.sh
```

备份默认写入项目下的 `backups/`，权限为仅当前用户可读。也可通过 `BACKUP_DIR=/安全挂载目录 ./scripts/backup.sh` 保存到独立磁盘。生产环境应再配置定时任务，并将备份同步到服务器之外；只有本机副本不算完整备份。

恢复前应先停止写入并再次确认目标数据库。恢复属于覆盖性操作，不由自动部署脚本执行：

```sh
docker compose exec -T database pg_restore \
  -U shiguang -d shiguang --clean --if-exists < backups/备份文件.dump
```

### 本地全栈联调

数据库默认不映射宿主机端口。以下命令启动不含公网 HTTPS 网关的基础服务，Web 入口仅绑定 `http://127.0.0.1:8088`：

```sh
docker compose up --build -d
./scripts/init-accounts.sh
```

初始化时交互输入两组用户名、昵称和密码；第一个账户为管理员，第二个为成员。重复初始化拒绝覆盖；密码不写入代码、命令参数或日志。

基础 Compose 与正式 Compose 都会以 `VITE_DEMO=false` 构建前端。正式部署额外启用 Caddy 自动签发 TLS 证书和 Secure Cookie。当前 Flyway 迁移随 API 启动运行；多实例或零停机部署前，应再拆成独立的一次性迁移任务。

### 媒体文件目录安全

Compose 已将独立 `media` 卷挂载到 API 容器的 `/app/media`，但当前没有把这个目录直接暴露给 Nginx 或公网。后续迁移照片和音频时，应继续由后端使用随机文件名保存，并通过鉴权下载接口读取；同时校验文件头、限制类型和大小、清理 EXIF、禁止脚本执行，并在响应中固定安全的 `Content-Type` 与 `Content-Disposition`。不要把上传目录映射成可执行的静态网站目录。

### 足迹长卷图片

足迹列表只返回城市、日期、说明、顺序及图片版本/尺寸/URL，不再将所有 Base64 图片塞进 JSON。图片使用独立的同源接口，按实际尺寸提供不超过 960、1920、3200px 的 JPEG 派生图，不放大小图。列表候选最多 1920px；首图优先加载，其余使用浏览器原生懒加载，3200px 只在“展开长卷 → 横向细读”时请求。浏览器懒加载有预取距离，不保证所有屏幕外图片都不请求。

- 手机和桌面卡片均**完整、等比例展示整幅横幅**，7:1 原图仍呈现约 7:1 的长卷效果，不裁切、不将手机卡片固定为 140px 高的局部窗口。桌面恢复紧凑长卷：日期、说明和操作叠在图内，不再附加大块图下信息区；平板按钮避免相互重叠。手机在图下仅保留一行日期/说明和展开入口，管理员另有一行操作按钮；说明单行省略、全文可在阅读器查看，触控范围至少 44px，不撑出整页横向滚动。城市保留为无障碍标题和阅读器标题，上传预览同样完整展示。
- “展开长卷”支持完整适应/横向细读；**细读默认显示中间**，手动滑动后不会因无关重渲染重新居中。支持触摸与方向键、Home/End、Esc 关闭和焦点恢复。列表失败和单图失败分别提供重试。
- 只改文字时不重新上传旧图；省略或传 null 的 `panoramaImage` 保留原图，选新图才换图并更新版本。管理写入仍需管理员权限和 CSRF，内容与动态在同一事务提交。
- Flyway V10 追加图片版本、尺寸和独立 `place_image_variants` 表。已有 `panorama_image`（或旧 `reference_image`）原值保留，首次读取图片时受限解码并生成、持久化派生图；以后不重复转码。坏图不会阻断列表，也不会清空原值，管理员可重新上传。历史图片首次打开有一次 CPU 成本；派生图增加数据库和备份体积，无需新增图片文件卷。
- 新上传支持真实 JPEG/PNG/WebP，服务端在解码前校验格式和尺寸，并限制字节数、像素数及并发；输出 JPEG 清除原始元数据，透明区域铺白底。WebP 用 TwelveMonkeys **读取**，Thumbnailator/ImageIO 生成 JPEG，不依赖原生 WebP 编码库。
- 私有图片和足迹元数据 `private, no-store`；只有当前允许访客访问的公开图片使用 `private, no-cache` + ETag，每次重新验证权限、存在性和版本后才可能返回 304。关闭公开后旧 ETag 也不能读取；错误为 no-store。这里没有给私图增加浏览器持久缓存、Service Worker 或公开静态目录。
- 直达 `/places` 不再顺带请求回忆、回收站和纪念日；这些资源按各自路由加载。退出/会话失效会取消旧请求、清理私有内容及长卷阅读器。

升级时先备份，再按上面的更新部署流程**同时重建前后端镜像**，由 API 启动执行 V10；不要手改已应用迁移或清空 places。仅替换前端静态文件不足以完成这次升级。

上线后用浏览器 Network 验证（本次未部署，须在实际服务器复测）：

1. 直达足迹，确认 `/places` JSON 不含 `panoramaImage`/Base64，且未伴随 `/memories`、`/trash`、`/anniversaries` 列表请求。
2. 观察各图片独立请求，列表不请求 3200 档；在长卷阅读器主动切到横向细读后才出现 `w=3200`。用手机检查卡片完整横幅、细读初始居中及页面无横向溢出。
3. 访客开放足迹时，从 Network 复制**公开**图片 URL，用 GET（不是 HEAD）检查响应和 ETag；带 `If-None-Match` 再次请求应为 304。关闭足迹公开后，同一 URL/ETag 必须为 403/no-store，而不是 304；检查 Nginx 后最终只有一条有效 Cache-Control。不要把登录 Cookie 或私有 URL 粘贴到共享日志。
4. 历史图第一次生成后再测热读取；在真实移动网络记录首图可见时间、传输大小和布局稳定性。不能把下方本机合成数据耗时当作线上 SLA。

参考：[Thumbnailator](https://github.com/coobird/thumbnailator)、[TwelveMonkeys](https://github.com/haraldk/TwelveMonkeys)、[MDN img 文档源码](https://github.com/mdn/content/blob/main/files/en-us/web/html/reference/elements/img/index.md)。本次只改足迹媒体，不代表回忆、相册和封面的媒体存储已整体迁移。

### 背景音乐

访客和登录成员都能看到右上角音乐按钮，控制**当前页面会话**的声音，默认开启，点击关闭、再次点击开启；不影响另一人的开关。播放时音符旋转，关闭时显示斜杠，系统“减少动态效果”设置下停止旋转但仍可播放。浏览器可能拦截首次有声自动播放，此时点击音乐按钮即可尝试播放，不会显示虚假的播放状态。

在管理页的“背景音乐”中，两位账号均可上传、设为背景音乐或删除歌曲。曲库和当前歌曲由服务端共同保存：任一人设定后，之后登录使用同一首歌；已打开的可见页面约每 15 秒同步，并在重新激活时刷新。换歌不会打开另一人的本地静音；切换站内页面不中断，当前歌曲单曲循环。删除当前歌曲会清空选择，不会自动换到另一首。上传不自动切歌。

- 支持 MP3（MPEG Layer III）与标准 PCM WAV，单个文件最大 20 MiB，默认最多 20 首、总容量 200 MiB。WAV 不接受浮点、压缩或 extensible 编码。服务端检查实际格式与完整性，不只检查扩展名。
- “允许精选内容公开”（SELECTED）时，访客可听**当前选中的背景音乐**，不依赖首页等模块开关；“完全私密”（PRIVATE）仍拒绝公开音乐请求。访客没有曲库、上传、删除或选曲权限。无选曲或完全私密时按钮仍显示，但无可播放歌曲，不跳转管理页。
- 公开只读入口为 `GET /api/v1/public/music`（仅当前选曲 ID/revision）与当前选曲的 `GET/HEAD /api/v1/public/music/tracks/{id}/content`，支持单段 Range；旧私有接口仍需登录。换歌、清空或删除后旧公开曲目 URL 的后续请求立即拒绝。快照、音频及错误均 no-store；客户端可见时约 15 秒同步撤销，无法撤回已下载/缓冲音频。文件仍以随机名称保存在私有媒体目录，不公开静态媒体目录。
- Compose 使用现有 `media` 卷和 `MEDIA_ROOT=/app/media`；非 Docker 运行默认在应用工作目录的 `./media`，建议显式设置 `MEDIA_ROOT`。目录须对应用账号可写，不能映射为公网静态目录。
- 镜像为新媒体卷准备非 root 权限；已有卷若由 root 创建，应先核对卷和容器账号，再在维护窗口修正该卷所有权，不能以 `chmod 777` 代替。
- 演示模式音乐只保留在当前页面内存中，刷新即清空；不支持跨设备共享，不向真实后端上传。正式模式不将曲库或音频保存到浏览器持久存储。

#### 数据库与媒体必须配套备份

`scripts/backup.sh` **仍只备份 PostgreSQL**，不能单独恢复上传的音乐。启用音乐后需将数据库备份与整个私有媒体卷作为一套保存，并限制归档文件访问权限。小站可在维护窗口停止 API 写入，再执行数据库备份并归档媒体卷，完成后恢复服务。例如（确认 Compose 项目和备份目录后手动执行）：

```sh
umask 077
# 停止 API，防止备份过程中上传/删除造成数据库与文件不一致。
docker compose stop api
./scripts/backup.sh
docker compose run --rm --no-deps --user root --entrypoint tar api \
  -C /app/media -czf - . > backups/同批次-media.tar.gz
docker compose start api
```

如果任一步失败也应恢复 API，并保留错误信息后重新制作完整配套备份。媒体归档应和对应的 `.dump` 一起保存到异地。恢复时先停止 API，确认目标为空或已另行备份，再恢复**同批次**数据库及媒体文件，核对非 root 应用账号可读写后启动 API。不得只恢复数据库，或混用不同批次的文件归档；应在独立环境实际验证曲目与播放可恢复。

不使用 Docker 时，在环境中设置 DATABASE_URL、DATABASE_USER、DATABASE_PASSWORD、COOKIE_SECURE，再执行：

```sh
cd backend
./mvnw test
./mvnw spring-boot:run
```

## 工程结构

- `frontend/src`：React 页面、语义样式、共享类型、API 客户端、日期规则。
- `backend/src/main/java/cn/shiguang`：安全配置、认证、回忆服务、纪念日、初始化命令。
- `backend/src/main/resources/db/migration`：数据库与会话表迁移。
- `contracts/openapi.yaml`：已实现 API 契约；`frontend/src/api/schema.d.ts` 为生成类型。
- `e2e`：浏览器验收、桌面/手机/深色截图与 Lighthouse 报告。
- `design-system/MASTER.md`：视觉设计决策与语义令牌约定。
- `compose.yaml`、`compose.prod.yaml`、Dockerfile、Nginx、Caddy：本地与正式环境部署配置。
